# Despair Board — บอร์ดเกมสืบสวนฆาตกรรมบนเว็บ (แนว Danganronpa)

เกม social deduction สำหรับ 3–15 คน เล่นผ่านเบราว์เซอร์ในห้องเดียวกัน
ทุกคนได้ตัวละครพร้อม **Ultimate** ที่ AI สุ่มให้ ทุกคืนมีฆาตกรรมที่ AI แต่งขึ้นสด ๆ
แล้วทุกคนต้องสืบสวนและโหวตหาคนร้าย

- เซิร์ฟเวอร์: Node.js + Express + Socket.IO (`server/`)
- หน้าเว็บ: HTML/CSS/JS ล้วน ไม่ต้อง build (`public/`)
- AI: Claude API ผ่าน `@anthropic-ai/sdk` (structured output ด้วย zod) และมี **โหมด mock** สำรองอัตโนมัติเมื่อไม่มี API key

---

## 1. ติดตั้งและรัน

ต้องมี Node.js 18 ขึ้นไป (ทดสอบกับ Node 26)

```bash
npm install
```

สร้างไฟล์ `.env` จากตัวอย่าง แล้วใส่ API key (ไม่ใส่ก็เล่นได้ในโหมด mock)

```bash
copy .env.example .env
```

รันเซิร์ฟเวอร์

```bash
npm start
```

เปิด <http://localhost:3000> — เพื่อนในวง Wi‑Fi เดียวกันเปิดได้ที่ `http://<IP เครื่องคุณ>:3000`
(ดู IP ด้วย `ipconfig`) ถ้าจะเล่นข้ามอินเทอร์เน็ตให้ใช้ tunnel เช่น `cloudflared tunnel --url http://localhost:3000` หรือ ngrok

ตอนพัฒนาใช้ `npm run dev` (รีสตาร์ตอัตโนมัติเมื่อแก้ไฟล์ใน `server/`)

### ตัวแปรใน `.env`

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `ANTHROPIC_API_KEY` | (ว่าง) | key ของ Anthropic ถ้าว่างจะใช้โหมด mock |
| `CLAUDE_MODEL` | `claude-opus-5-5` | โมเดลที่ใช้เจนเนื้อหา (`claude-sonnet-5-5` ถูกกว่าและเร็วกว่า) |
| `AI_MODE` | (ว่าง) | ตั้งเป็น `mock` เพื่อบังคับใช้ข้อมูลตัวอย่างแม้มี key |
| `AI_FALLBACKS` | (ว่าง) | ตั้งเป็น `off` เพื่อปิด server-side refusal fallback |
| `PORT` | `3000` | พอร์ตเว็บ |
| `MIN_PLAYERS` | `3` | ผู้เล่นขั้นต่ำ (รวมบอท) |
| `NIGHT_TIMEOUT_MS` | `120000` | เวลาที่ฆาตกรมีสำหรับเลือกเป้าหมาย หมดเวลาแล้วระบบสุ่มให้ |
| `MAX_RUNOFFS` | `2` | จำนวนรอบโหวตตัดสินสูงสุดเมื่อคะแนนเสมอ ก่อนสุ่ม |
| `EXECUTE_WRONG_VOTE` | `false` | ถ้า `true` คนที่ถูกโหวตผิดจะถูกประหารด้วย |
| `REVIVE_CHANCE` | `0.2` | โอกาส (0–1) เกิดอีเวนต์คืนชีพตอนเริ่มวันใหม่ ตั้ง `0` เพื่อปิด |

## 2. วิธีเล่น

1. **สร้างห้อง** ใส่ชื่อ → กด "สร้างห้องใหม่" ได้รหัสห้อง 4 ตัว ส่งให้เพื่อนกด "เข้าร่วมห้อง"
2. **ล็อบบี้** หัวห้อง (คนแรกที่เข้า) เลือกจำนวน **บอท** เพื่อเติมผู้เล่น แล้วกด "เริ่มเกม"
3. **สุ่มตัวละคร** ทุกคนได้ตัวละคร 1 ตัว (จาก 15 ตัว mock ชื่อแนวญี่ปุ่นใน `server/characters.js` เช่น ฮายาชิ ฮินาตะ, คุโรซาวะ เรน) และ AI สุ่ม Ultimate ให้
   - AI ระบุว่า Ultimate ไหน *มีผลต่อการสืบสวน* หรือ *เพิ่ม/ลดความเชื่อใจ* (เช่น นักสืบ นักเคมี ช่างไฟ แฮกเกอร์ ผู้นำ) แต่ระบบจะ **ซ่อนเป็น `???` จริงแค่ 1–2 คน** (`HIDDEN_ULTIMATE_RATIO`/`HIDDEN_ULTIMATE_MAX`: 10 คน → 2, 7 คน → 1) ที่เหลือเปิดเผยตามปกติ
   - อีก **1 คนได้ "โรลปลอม"** (`FAKE_ROLES`): Ultimate ที่คนอื่นเห็นเป็นของปลอม (AI คิด "ฉากบังหน้า" ให้เข้ากับตัวละคร) มีแค่เจ้าตัวที่รู้ของจริง จะถูกเปิดโปงเมื่อเป็นคนร้าย/เหยื่อที่ตัดสินแล้ว หรือตอนจบเกม
   - เจ้าของ `???` จะรู้หรือไม่รู้ สุ่ม 50/50 (ถ้าไม่รู้ อาจ "ตระหนัก" ได้เมื่อเกิดคดีที่เกี่ยวข้อง) ส่วนเจ้าของโรลปลอมรู้ของจริงเสมอ
   - ทุกคนเห็นชื่อผู้เล่น ชื่อตัวละคร และ Ultimate (จริง / ปลอม / `???`) ของกันและกัน
4. **กลางวัน** AI สร้างสถานที่ปิดตาย 1 แห่ง พร้อมอุปกรณ์ 7–10 ชิ้น คุยกันในแชทได้ จนทุกคนกด **เข้านอน** (หัวห้องบังคับได้)
5. **กลางคืน** ระบบสุ่มฆาตกร 1 คน (รู้แค่ตัวเอง) ให้เลือกเป้าหมาย 1 คน
6. **เกิดเหตุ** AI แต่งเหตุการณ์ฆาตกรรมโดยยึดว่าต้องมีฆาตกรและเป้าหมายเกี่ยวข้องเสมอ แต่
   - คนตายเป็นใครก็ได้ (เป้าหมาย / ฆาตกรเอง / คนอื่นที่บังเอิญมาเห็น)
   - **คนร้ายตัวจริง**อาจไม่ใช่ฆาตกรที่ระบบเลือก (เช่น เป้าหมายสู้กลับ หรือบุคคลที่สามฉวยโอกาส)
   - **วิธีการต้องสมจริง**: วิธีฆ่าและวิธีปกปิดเป็นการกระทำจริงด้วยของในสถานที่ ทุกการปกปิดทิ้งร่องรอย (เช่น นักเคมีผสมน้ำยาล้างคราบ → เหลือกลิ่นฉุนและขวดพร่อง) และร่องรอยนั้นต้องจำกัดวงผู้ต้องสงสัยเหลือ 2–3 คน ไม่ใช่ชี้ตัวทันที
   - Ultimate ของคนร้ายใช้ได้ **เฉพาะเมื่อมีกลไกจริง** (นักเคมี ช่างไฟ แฮกเกอร์ พยาบาล นักแสดง ฯลฯ) นักเต้น/นักทำขนม/เกมเมอร์ "ปกปิดร่องรอย" ไม่ได้ และหลายคดีไม่ใช้ Ultimate เลย
   - AI ต้องระบุ **ตำแหน่งจริงของทุกคน** ในคืนนั้น และ **เหตุการณ์ย่อย** 4–7 รายการ (ใครเห็นใครที่ไหนกี่โมง ใครนั่งคุยกับใคร) โดยมี 2–3 คนที่ดูน่าสงสัย: หนึ่งในนั้นคือคนร้าย ที่เหลือมีเหตุผลบริสุทธิ์ที่พยานคนอื่นยืนยันได้
7. **สืบสวน** ทุกคนเห็นเหมือนกันแค่: สภาพศพที่ตาเปล่าเห็นได้ อุปกรณ์ต้องสงสัย และความผิดปกติในที่เกิดเหตุ — **ไม่มีใครรู้ทุกอย่าง**
   - ทุกคนรู้ **"สิ่งที่ตัวเองทำคืนนี้"** (เฉพาะตัวเอง) และ **เหตุการณ์ที่ตัวเองเห็นหรืออยู่ด้วย** (รู้เฉพาะคนในเหตุการณ์นั้น เช่น สองคนที่นั่งคุยกันรู้ทั้งคู่ คนที่ตื่นมาเห็นเตียงว่างรู้คนเดียว) ต้องเอามาเล่าในแชทเพื่อต่อภาพให้ครบ
   - คนร้ายตัวจริงเห็นเรื่องราวทั้งหมด วิธีการ ร่องรอยที่ตัวเองทิ้งไว้ และ "จุดที่อาจพลาด" แบบไม่ฟันธง (ไม่รู้แน่ว่าใครเห็นอะไร)
   - คนที่อยู่ในเหตุการณ์อาจได้ "เบาะแสส่วนตัว" เพิ่ม (สิ่งที่รับรู้คนเดียว เช่น ได้ยินเสียง เห็นเงา)
   - คนที่ Ultimate เกี่ยวข้องได้ "สัญชาตญาณ" เพิ่ม (เช่น ช่างไฟรู้ว่าเบรกเกอร์ถูกสับด้วยมือ ไม่ใช่ไฟตก)
   - คุยกันในแชทแล้วโหวต → กด **ยืนยันโหวต** เมื่อทุกคนยืนยันระบบจะตัดสิน (หัวห้องปิดโหวตก่อนได้)
8. **ผลการตัดสิน**
   - โหวตถูก → คนร้าย **ถูกประหาร** (ออกจากเกม นับว่าไม่รอด)
   - โหวตผิด → คนร้าย **หนีรอด** (ออกจากเกม นับว่ารอด) ส่วนคนที่ถูกโหวตผิดยังอยู่ต่อ (ตั้ง `EXECUTE_WRONG_VOTE=true` ถ้าอยากให้ถูกประหารด้วย)
   - คะแนนเสมอ → **โหวตรอบตัดสิน** เฉพาะคนที่เสมอกัน (สูงสุด `MAX_RUNOFFS` รอบ ถ้ายังเสมอจึงสุ่ม)
   - เฉลยความจริงทั้งหมด: วิธีการ การปกปิดและร่องรอย **เส้นทางการไขคดี** (ลำดับเหตุผลที่ควรสรุปได้ถ้าทุกคนเล่าสิ่งที่รู้) ตำแหน่งจริงของทุกคน เหตุการณ์ย่อยทั้งหมดพร้อมว่าใครรู้บ้าง และ Ultimate จริงของคนร้ายกับเหยื่อ (ถ้าถือโรลปลอมจะถูกเปิดโปง)
9. **เช้าวันใหม่** อาจเกิด **อีเวนต์พิเศษ "คืนชีพ"** (โอกาส `REVIVE_CHANCE`, เฉพาะเหยื่อ และคนละครั้ง): AI แต่งสถานการณ์ประกอบว่าทำไมเหยื่อถึงไม่ได้ตายจริง แล้วกลับเข้าเกม
10. วนข้อ 4–9 (สถานที่ใหม่ทุกวัน) จนเหลือผู้เล่น ≤ 1 คน แล้วแสดง **สรุปผล: ใครรอด ใครไม่รอด**

### สรุปผลท้ายเกม (ไม่มีระบบอันดับ)

| สถานะ | ใครบ้าง |
|---|---|
| **รอดชีวิต** | ผู้เล่นที่อยู่จนจบเกม และคนร้ายที่หนีรอดจากการโหวต |
| **ไม่รอด** | เหยื่อ คนร้ายที่ถูกจับและประหาร (และผู้บริสุทธิ์ที่ถูกโหวตผิด ถ้าเปิด `EXECUTE_WRONG_VOTE`) |

> ระบบอันดับถูกถอดออกตามที่ตกลง ถ้าอยากเพิ่มกลับมาภายหลัง ให้ต่อจาก `computeOutcome()` ใน `server/game.js` ซึ่งมีข้อมูลชะตากรรมและรอบที่ออกจากเกมของทุกคนอยู่แล้ว

### กติกาเสริมที่ระบบตัดสินใจไว้ (แก้ได้)

- โหวตเสมอกัน → โหวตรอบตัดสินเฉพาะคนที่เสมอ (บอทโหวตใหม่เองได้) ถ้ายังเสมอครบ `MAX_RUNOFFS` รอบจึงสุ่ม
- ผู้ที่ตาย/ออกจากเกมแล้วดูเกมต่อได้แต่พิมพ์แชทและโหวตไม่ได้ (พิมพ์ได้อีกครั้งเมื่อเกมจบ) ยกเว้นถูกคืนชีพจากอีเวนต์พิเศษ
- อีเวนต์คืนชีพเกิดได้เฉพาะเหยื่อ (ไม่ใช่คนร้ายที่ถูกประหาร) คนละ 1 ครั้ง และเรื่องราวจะถูกแต่งให้สอดคล้องกับสาเหตุการตายในคดีที่เฉลยไปแล้ว
- ฆาตกรไม่เลือกเป้าหมายภายใน `NIGHT_TIMEOUT_MS` → ระบบสุ่มให้
- หัวห้องหลุด → โอนสิทธิ์ให้คนถัดไปที่ยังออนไลน์ รีเฟรชหน้าแล้วกลับเข้าห้องเดิมได้ (จำด้วย localStorage)
- บอทจะเข้านอน/เลือกเป้าหมาย/โหวตเอง (โหวตถูก 35% ถ้าไม่ใช่คนร้าย)

## 2.5 เล่นกับเพื่อน

เซิร์ฟเวอร์ฟังทุก interface (`0.0.0.0`) และหน้าล็อบบี้มีปุ่ม **🔗 คัดลอกลิงก์เชิญ** (`/?room=XXXX`) ที่เปิดแล้วกรอกรหัสห้องให้เอง ผู้เล่นแค่ใส่ชื่อแล้วกดเข้าร่วม ลิงก์ใช้ origin ที่หัวห้อง "เปิดอยู่" ดังนั้นให้หัวห้องเปิดเกมผ่านที่อยู่ที่เพื่อนเข้าถึงได้ก่อน แล้วค่อยคัดลอกลิงก์

| วิธี | เหมาะกับ | ทำอย่างไร |
|---|---|---|
| **Wi-Fi เดียวกัน (LAN)** | เล่นในบ้าน/ห้องเดียวกัน | รัน `npm start` แล้วดูบรรทัด "เพื่อนใน Wi-Fi เดียวกันเข้าได้ที่ http://192.168.x.x:3000" ส่งลิงก์นั้นให้เพื่อน (ถ้าเข้าไม่ได้ ให้ Windows Firewall อนุญาต Node.js บนเครือข่ายส่วนตัว) |
| **อินเทอร์เน็ต แบบชั่วคราว** | เล่นกับเพื่อนต่างที่ ไม่ต้องสมัครอะไร | ติดตั้ง [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) (`winget install Cloudflare.cloudflared`) แล้วรัน `npm run share` ควบคู่กับ `npm start` จะได้ URL `https://xxxx.trycloudflare.com` ใช้ได้จนกว่าจะปิดหน้าต่าง |
| **อินเทอร์เน็ต แบบถาวร (แนะนำ)** | เปิดห้องได้ทุกเมื่อโดยไม่ต้องเปิดคอม ไม่ต้องอยู่ Wi-Fi เดียวกัน | Deploy ขึ้น Render ฟรีผ่าน GitHub ตามหัวข้อ **2.6** ด้านล่าง (มี `render.yaml` และ `Dockerfile` ให้แล้ว) |

ข้อควรรู้ตอนเล่นจริง:

- รหัสห้อง 4 ตัวอักษรไม่มีรหัสผ่าน ใครได้ลิงก์ก็เข้าได้ จึงเหมาะกับการส่งในกลุ่มเพื่อนเท่านั้น
- ผู้เล่นที่หลุด (ปิดแท็บ/เน็ตหลุด) กลับเข้าห้องเดิมได้อัตโนมัติด้วยชื่อเดิมบนเบราว์เซอร์เดิม ระหว่างนั้นหัวห้องใช้ปุ่ม "บังคับเข้านอน" / "ปิดโหวตตอนนี้" ให้เกมเดินต่อได้
- ถ้าหัวห้องหลุด คนถัดไปจะเป็นหัวห้องแทนอัตโนมัติ ห้องที่ไม่มีใครอยู่เกิน 2 ชั่วโมงจะถูกลบ
- รองรับมือถือ (เลย์เอาต์เรียงเป็นคอลัมน์เดียว)

## 2.6 ขึ้นเซิร์ฟเวอร์จริงผ่าน Git (Render ฟรี) — ใช้เวลาราว 10 นาที

เกมเป็นเซิร์ฟเวอร์ Node ตัวเดียว (Express + Socket.IO) ห้องเก็บในหน่วยความจำ จึง deploy ได้กับโฮสต์ที่รัน Node ยาว ๆ และรองรับ WebSocket เช่น **Render** (ฟรี ไม่ต้องใส่บัตร), Koyeb, Railway, Fly.io หรือ VPS ใด ๆ ที่มี Docker
โฮสต์แบบ serverless (Vercel, Netlify, Cloudflare Pages) **ใช้ไม่ได้** เพราะไม่รองรับการเชื่อมต่อค้างไว้

### ขั้นตอน (Render)

1. **สร้าง repo บน GitHub** (กด New repository ตั้งชื่อ เช่น `danganronpa-web` ไม่ต้องติ๊กสร้าง README) แล้ว push โค้ดจากเครื่องนี้ (โฟลเดอร์นี้มี git repo และ commit แรกอยู่แล้ว):

   ```bash
   git remote add origin https://github.com/<ชื่อผู้ใช้>/danganronpa-web.git
   ```

   ```bash
   git push -u origin main
   ```

2. **สมัคร Render** ที่ https://render.com ด้วยบัญชี GitHub (ฟรี ไม่ต้องใส่บัตร)

ถ้า repo เป็น public จะใช้ปุ่มนี้แทนข้อ 3 ได้ (แก้ `<ชื่อผู้ใช้>` ในลิงก์ก่อน):
`[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/<ชื่อผู้ใช้>/danganronpa-web)`

## 3. โหมด AI และค่าใช้จ่าย

ต่อ 1 รอบเกมจะเรียก Claude ประมาณ 2–3 ครั้ง (สถานที่ + คดี + อีเวนต์คืนชีพถ้าเกิด) บวกตอนเริ่มเกม 1 ครั้ง (Ultimate)
แต่ละครั้งส่งราว 1.5–3K โทเค็นเข้า และได้ 1–3K โทเค็นออก ที่ราคา Opus 5.5 ($4/$20 ต่อล้านโทเค็น)
เกม 15 คน 7 รอบ จึงอยู่ราว ๆ ไม่กี่สิบเซนต์ ถ้าอยากประหยัดตั้ง `CLAUDE_MODEL=claude-sonnet-5-5`

สิ่งที่ตั้งไว้ในโค้ด (`server/ai.js`):

- ใช้ `client.beta.messages.parse` + `betaZodOutputFormat` เพื่อให้ได้ JSON ตรงตาม schema เสมอ
- `output_config.effort`: `medium` สำหรับ Ultimate/สถานที่, `high` สำหรับคดี
- เปิด **server-side refusal fallback** (`fallbacks: "default"`) ไว้ตามคำแนะนำของ Anthropic ปิดได้ด้วย `AI_FALLBACKS=off`
- ตรวจสอบผลลัพธ์ (เหยื่อ/คนร้ายต้องยังมีชีวิตและไม่ใช่คนเดียวกัน, มี method/whereabouts/deductionChain ครบ) ถ้าผิดจะขอใหม่ 1 ครั้ง ถ้ายังผิดหรือ API ล่ม จะใช้ mock แทนรอบนั้นโดยเกมไม่สะดุด
- prompt คดีบังคับความสมจริง: Ultimate ใช้ได้เฉพาะเมื่ออธิบายกลไกได้ ทุกการปกปิดทิ้งร่องรอย ตำแหน่งทุกคนต้องครบ และต้องส่ง `deductionChain` ที่ไขได้จากข้อมูลที่แจกจริง
- ตอนเริ่มเซิร์ฟเวอร์จะเช็ก credentials ด้วย `models.list` (ไม่เสียโทเค็น) ถ้าไม่ผ่านจะเป็นโหมด mock และหน้าเว็บจะแสดงป้าย `AI: Mock`

โหมด mock (`server/mock.js`) มี Ultimate 30 แบบ สถานที่ 6 แห่ง และเทมเพลตคดีที่ยังคงตรรกะเดียวกัน: ตาราง "กลไกจริง" ของ Ultimate 10 แบบ (นักเคมี ช่างไฟ แฮกเกอร์ พยาบาล นิติเวช นักแสดง สายลับ นักล้วงกระเป๋า นักฆ่า นักสืบ) Ultimate อื่นใช้วิธีธรรมดา, ตำแหน่งทุกคนพร้อมหลักฐานลวง 1 คนที่มีพยานยืนยัน, จุดอ่อนของคนร้าย 1 จุด และเส้นทางการไขคดี

## 4. โครงสร้างโปรเจกต์

```
server/
  index.js        Express + Socket.IO, จัดการห้องและ event จากผู้เล่น
  game.js         state machine ของเกม (lobby → day → night → incident → investigation → trial_result → ended)
  ai.js           เรียก Claude (zod schema + prompt) และ fallback ไป mock
  mock.js         ข้อมูลตัวอย่างสำหรับโหมดไม่มี API key
  characters.js   ตัวละคร mock 15 ตัว (ชื่อ ลักษณะ นิสัย)
public/
  index.html / style.css / app.js   หน้าเว็บทั้งหมด (render จาก state ที่เซิร์ฟเวอร์ส่งมาเฉพาะบุคคล)
test/
  simulate.js     จำลองเกมเต็มรอบด้วย mock ตรวจการซ่อนข้อมูล โรลปลอม โครงสร้างคดี และสรุปผล
```

เซิร์ฟเวอร์ส่ง `state` ที่ **กรองแล้วเฉพาะผู้เล่นคนนั้น** (`Game.viewFor(playerId)`) ดังนั้น Ultimate ที่ซ่อน เรื่องราวของคนร้าย และเบาะแสส่วนตัวของคนอื่นจะไม่ถูกส่งไปที่เบราว์เซอร์ของคนที่ไม่มีสิทธิ์เห็นเลย

## 6. สิ่งที่ยังไม่มี / ต่อยอดได้

- ห้องเก็บในหน่วยความจำ ถ้ารีสตาร์ตเซิร์ฟเวอร์เกมที่ค้างอยู่จะหาย
- ยังไม่มีระบบล็อกอิน ใครรู้รหัสห้องก็เข้าได้ (เหมาะกับเล่นในกลุ่มเพื่อน)
- ตัวละคร 15 ตัวเป็น mock ถ้าต้องการให้ AI สุ่มชื่อ/ลักษณะด้วย เพิ่มฟังก์ชันใน `ai.js` คล้าย `generateUltimates`
- ระบบอันดับถูกถอดออกตามที่ตกลง (เหลือแค่รอด/ไม่รอด) เพิ่มกลับได้ภายหลังจากข้อมูลใน `computeOutcome()`
- อีเวนต์พิเศษตอนนี้มีแค่ "คืนชีพ" โครงสร้าง `specialEvent.type` รองรับการเพิ่มอีเวนต์ชนิดอื่นในอนาคต
- ไอเดียเพิ่ม: เสียง/เอฟเฟกต์ตอนพบศพ, จับเวลาช่วงโหวต, แชทกระซิบ, บันทึกเกมเป็นไฟล์
